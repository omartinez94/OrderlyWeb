Design rationale — numbered annotations

Cross-ref research/competitive-analysis-restaurant-crm.md §5.3 + website-spec.md §5.4
  1. 1

    Restaurant switcher (top bar)

    Top-bar dropdown — confirmed by all five competitors (Toast, Square, Lightspeed, SevenRooms, OpenTable). Implements website-spec.md §5.2. Hidden when user has access to one restaurant. Cache invalidation on switch drops all RTK Query tags for the previous restaurant.

  2. 2

    Filter row — status chips with counts

    Status filter rendered as toggle chips, not a dropdown — pattern from Square Dashboard ("live filters with counts"). Each chip carries a count so the operator sees how many orders will appear if they toggle. Status colors match website-spec.md §6.4 exactly (blue / amber / yellow / emerald / teal / gray / red / purple). Type / Table / Date selectors are secondary — narrower, less visual weight. Search field right-aligned.

    ↳ Active filter summary line below the bar keeps the operator oriented on what's currently showing.
  3. 3

    Bulk action bar (only when ≥ 1 row selected)

    Slot-in toolbar appears above the table — answers website-spec.md §12 #3 ("Do managers need a bulk action panel?"). Includes Mark Ready, Reassign, Apply Discount, Cancel. Destructive action (Cancel) gets rose-200 border as visual warning. Handles "Mixed statuses — actions below apply individually" because Cancel on a `Ready` row means different state transitions than on a `Preparing` row.

  4. 4

    Data table — the canonical list pattern

    Sortable columns, status pills (left edge dot + label), monospace for numbers/IDs (a Square convention). New rows get flash-new animation (2 s pulse) on blue background tint, derived from Toast's "auto-highlight new orders" pattern. All 8 status states represented in this dataset to show the full color palette.

    ↳ Total $ column right-aligned, monospaced, no thousand separators under $10k (matches how operators read totals).
  5. 5

    Pagination footer

    Cursor-style pagination with explicit page numbers + "Per page" selector. Server-side driven (RTK Query page param). For high-volume restaurants (200+ orders/day) an Infinite Scroll option should be considered for V2 — see website-spec.md §12 open questions.

  6. 6

    Live connection status (always-visible footer)

    website-spec.md §5.4 mandates a "Connection status indicator (connected/reconnecting/disconnected)". Placed at the bottom of the table area, not in the top bar — visible while the operator scans rows, not just on page load. Shows a micro-summary: 8 active · 12 preparing · 3 ready · 1 on hold (cross-zone signal that the kitchen is keeping up).

  7. 7

    Compare-with… toggle (differentiation vs competitors)

    Gap opportunity from research/competitive-analysis-restaurant-crm.md §4.3 #3: none of the 5 competitor platforms surface true side-by-side KPI comparison between restaurants a manager owns. Shown as a dashed-border ghost button next to the restaurant switcher — pre-MVP, but the route is reserved.
