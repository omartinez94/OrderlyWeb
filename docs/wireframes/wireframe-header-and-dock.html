Annotation pins — what to look at, and why

1 macOS Apple-menu pattern · left cluster

Orderly brand mark (left) → app name → app menus (File / Edit / View / Window / Help). The brand mark replaces the literal Apple logo — same affordance: click → dropdown with app-level actions (preferences, about, sign out, hide). Menus become dropdowns on click, identical to native macOS.

2 System tray · right cluster

Six controls right-aligned: Spotlight (Cmd+K), theme toggle, notification bell (with badge), fullscreen, clock, user avatar. Sourced directly from macOS — operators get the muscle memory for free. Notification badge stays visible across every page, including while focused on table content.

3 Always-visible mono clock

Mono 11.5 px · right-aligned · no seconds (matches macOS clock default). Click → opens a small calendar popover. Operators don't need to look at the clock app or their phone for shift changeover or ticket-urgency timing.

4 1-click theme toggle

Sun/moon icon · instantly swaps system bar + utility bar + dock + page theme via data-theme="dark" on <html>. Persisted in localStorage. KDS monitors who need dark mode no longer have to go to Settings to toggle.

5 Same bar on dark canvas (kitchen zone)

Glass darkens, Orderly brand mark picks up kitchen-green accent, persona-tinted avatar (Maria = cyan → Carlos = orange). Operators moving between zones keep the same anchoring visual.

6 Same control set survives across personas

Cashier, Waiter, Host, Manager, KitchenStaff, SuperAdmin — every persona sees the same system bar. The only thing that varies is the avatar (and shape, e.g. on dark canvas vs light).

7 Cross-zone consistency — same dock on dark canvas

Kitchen zone uses the same dock geometry but a warmer glass (dock-warm) and a subtle amber inset-shadow hint at "kitchen glow". Operators moving between zones get the same muscle memory.

8 Dock item anatomy — three interaction states

Default · Hover (lift+scale+tooltip) · Active (cyan dot) · With badge. All 4 states use the same bounding box for the icon container, so the layout never shifts between hover/active — only the icon scales and lifts.

9 Hover lift behavior

transform: translateY(-8px) scale(1.15) on hover. Gives the same magnification feel as the real macOS dock. Pairs with tooltip 54 px above showing route + spec link.

10 Active state — cyan dot indicator

Active icon gets a 5×5 px cyan dot at bottom: -12px with glow. Always visible — never animates away. Lets the operator confirm "what zone am I in" even with peripheral vision while reading page content.

11 Live-count badge · color-coded by zone

Red badge for orders/tables, green for kitchen. 16×16 px, top-right of icon, with a 2-px ring matching the dock background so it stays legible on any hover state. Counts pushed via SignalR.

12 Responsive collapse — system bar always survives

All three breakpoints keep the system bar — it's the OS-level chrome that operators expect to see at all sizes. ≥1280: 3 tiers · 768–1279: compressed dock (30 px icons, fewer menus visible) · <768: hamburger replaces dock row, system bar still present.

13 Total header height: ~126 px

30 px (sysbar) + 36 px (utility) + 60 px (dock) = 126 px. Saves vs a left-sidebar layout (~240 px wide × full height) by reclaiming 60+ px vertically while gaining a global control surface. Mobile shrinks to ~70 px (just system bar + utility, no dock row).

Implementation hand-off notes

Component shape — now 3 components

SystemBar (NEW — top tier) · UtilityBar (middle tier) · DockNav (bottom tier). SystemBar consumes theme state + persona + notification count. UtilityBar consumes restaurant context. DockNav consumes a route-list config (icon + spec-link + active match) + per-route badge counts from useDockCounts().

Styling

Tailwind utilities + custom classes .sysbar / .sysbar-dark / .sysbar-menu / .sysbar-icon-btn / .sysbar-clock / .sysbar-user · .dock / .dock-warm / .dock-item / .dock-tip / .dock-badge. Glass effect (backdrop-filter: blur(20px) saturate(180%)) supported in all modern browsers.

State

System bar: theme (Zustand store or Redux Toolkit slice), notifications (SignalR /hubs/notifications), current persona. Utility bar: active restaurant, live status. Dock nav: active route from useRouter(), badge counts from RTK Query + SignalR.

App menus (File/Edit/View/etc.)

Wire to real behaviors: File → New Order / Export / Sign out · Edit → Undo / Find · View → Toggle theme / Toggle notifications / Fullscreen · Window → Minimize / Zoom · Help → Docs / Keyboard shortcuts / About. HeadlessUI Menu component recommended for the dropdowns.

Accessibility

Each system bar button = real <button> with aria-label. Dock items get aria-current="page" when active. Keyboard nav: arrow keys cycle between dock icons · Tab cycles header-level · ESC closes open dropdowns. Spotlight opens via Cmd+K (or Ctrl+K on Windows) — see spec §12.

Theme persistence

Toggle sets document.documentElement.dataset.theme + persists to localStorage (not a cookie — localStorage is fine for UI prefs, not auth). Tailwind config: enable darkMode: ['class', '[data-theme="dark"]']. HeadlessUI components use .dark modifier.
