Restaurant Dashboard — Combined (Card Grid + Overview)

Route /site/restaurant · Same data, two layouts · Pin-prefix A = Card Grid (analytical) · Pin-prefix B = Overview (operational) · Source: research §4.1, §4.3, §5.1

v0.2 16 annotation pins (A1–A8 + B1–B8)

Both layouts ship — default per persona

§ A — Card Grid (analytical persona)
Default for: RestaurantAdmin · Manager (review mode)
  • 4 large KPI cards with sparklines + deltas
  • Revenue trend bar chart (7 days)
  • Top items list with progress bars
  • Server leaderboard (research §4.3 #2)
  • Live activity feed as a side stream
§ B — Overview (operational persona)
Default for: Manager (shift mode) · Waiter with admin tasks
  • 4 compact KPI cards (smaller, status pills)
  • Compact revenue trend (same data, less prominent)
  • Server leaderboard (podium visualization)
  • Live orders panel — actionable row-per-order
  • Urgent-row highlighting (rose + ⚠ for overdue)

Both views pull from the same RTK Query endpoints (kpiSummary, revenueTrend, topItems, serverLeaderboard, liveOrders) — only the layout component differs. Toggle in user prefs OR route-based on persona claim from JWT.

Annotation pins — combined rationale (A1–A8 + B1–B8)

§ A — Card Grid (analytical)

A1KPI card anatomy

4-card row · same layout primitive everywhere: icon · label · big mono number · delta + sparkline. Scales to any KPI (revenue, tickets, time, utilization, staff count, NPA — research §4.2 #6).

A2Time-range segmented control

Top-right segmented control — borrowed from Toast Dashboard + Square Reports. Default Today · Yesterday shown active as example. Custom opens date-range popover. URL-stateful (?range=yesterday).

A3Sparkline component (reusable)

Tiny inline-SVG sparkline with last-point dot. Used in 4+ places on this dashboard, plus staff activity, ticket volume, analytics. Build as <Sparkline values color /> with color prop.

A4Revenue trend · 7-day bar chart

Switchable between $ / Orders / Avg metric. Today (Mon) gets a neutral zinc color (data still collecting). Saturday is ringed in cyan to indicate peak. 7 bars fit comfortably at 1/7 width each.

A5Server leaderboard · actionable personnel data

Research §4.3 #2 gap. Pink highlight if any server is >15% below average → actionable for floor reassignment. Sortable by tickets / revenue / avg-ticket. Click row → server detail / shift history.

A6Top items · progress-bar visualization

Wider gradient-bar (emerald-500) for higher rank. Tap row → item detail. When a promo menu is active, the top 1 item shows a promo badge. Bar width shows relative ranking, not absolute sales.

A7Live activity feed · SignalR-driven

Subscribed to /hubs/orders + /hubs/notifications. Color-dot = event type (green=ready, blue=new, yellow=kitchen, rose=cancel, zinc=mod). Last 30 min only — beyond that lives at /site/admin/activity (reserved route, see spec §4.3).

A8"Compare with…" toggle · competitive edge

Dashed-border ghost in utility bar. Research §4.3 #3 — none of the 5 competitors have true side-by-side multi-restaurant KPI comparison. Pre-MVP; route /site/admin/compare reserved.

§ B — Overview (operational)

B1Compact KPI snapshot (2×2)

Same 4 KPIs but ~30% smaller. Slot reads "what's the state of the world right now" not "let me analyze trends". Sparkline, status pills, mini progress bar replace the deeper metrics.

B2Trend stays · but compact

Same 7-day chart, ~30% less prominent. Manager glances "are we up/down" without leaving. The toggle is now a dropdown (saves space). Same data, lower weight.

B3Live orders panel · the reason this view exists

Right panel = the new addition vs Card Grid. 8 currently-active orders as a vertical feed of actionable rows. Color-coded urgency (urgent #1046 with 21:10 elapsed gets rose bg + ⚠) — at-a-glance triage.

B4Filter row · All · Live only · My section

Three quick filters in the right panel header. "My section" is a research gap — none of the 5 competitor platforms surface per-server filtering at this level. Especially valuable for senior waiters who also act as shift supervisors.

B5Persona-tuned · Shift-Manager

Built for the manager mid-floor, not one doing P&L review. "Updated 2 sec ago" + live pulse near header reassures this isn't a stale snapshot. Density is intentionally lower than Card Grid.

B6Compact server leaderboard · podium visualization

Same server data as §A but rendered as a podium (1-2-3) instead of a table. Winner gets amber ring. Takes ~50% less vertical space while keeping the same scanability.

B7Split layout · "two adjacent rooms"

Same split pattern as Wireframe C's combined-ops experimental layout. At ≥1440 px both panels breathe. At <1280 px the right panel collapses to a slide-over drawer triggered by the orders dock badge.

B8Recent events merge at the bottom

Below the active orders, a small "Last events" list. Same /hubs/orders stream. Tells the manager what just happened (cancellations, reservations, modifications). Click → opens full /site/admin/activity route.

Implementation hand-off (single component set, two layouts)

Components built ONCE, rendered in TWO layouts
  • KpiCard — props: variant={'cardgrid'|'compact'}, label, value, delta, sparkline
  • RevenueTrendChart — bars; takes metric + range props
  • TopItemsList — used in §A; could feed §B's "Top today" podium (B6 area)
  • ServerLeaderboard — variant={'table'|'podium'}
  • LiveActivityFeed — uses §A directly; §B replaces it with LiveOrdersPanel
  • LiveOrdersPanel — only in §B; row-click → /orders/:id
Data sources (RTK Query + SignalR)
  • useGetKpiSummaryQuery — revenue, tickets, time, util — cached 60s
  • useGetRevenueTrendQuery — range param, cached per range
  • useGetTopItemsQuery — by quantity or revenue
  • useGetServerLeaderboardQuery — by tickets / sales / avg
  • /hubs/notifications — activity feed events
  • /hubs/orders — live orders panel (B only)
