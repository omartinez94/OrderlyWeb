Annotation pins — what to look at, and why

1 Big status pill + amber overdue flag

Status pill is duplicated at top of the page (same as list) PLUS this order-specific amber "Overdue" flag because elapsed > 20 min. The flag is what triggers Carlos (waiter) to take action — either bump kitchen or escalate to manager. Cross-ref KDS time-color system, spec §6.5.

2 Inline approval queue

Waiters can't apply discounts > $5 without manager approval (research §4.3 gap #5). When Sofia applies the 10% VIP discount, Maria sees a yellow review bar on the order detail with Approve / Reject / View diff buttons. Replaces a separate inbox — see spec §12 #5.

3 Items table with highlighted additions

Every line item shows qty · name · station · cook time · modifiers · unit · subtotal · delete. Items added after the order was sent to kitchen get a soft amber background tint (#1046 +1 Espresso) — visual cue that this is a "post-fire" modification the kitchen should bump.

4 Action button menu (Print · Send to Cashier · Mark Ready · …)

Order-level actions, not item-level. Right-side destructive (trash) action stays icon-only to avoid accidental cancel. Buttons disable based on state (e.g. Send to Cashier disabled if order already at cashier, Mark Ready disabled if status isn't Preparing).

5 Totals breakdown — transparent math

Subtotal · Discount · Service · Tax · Total — each line explicit. The discount line shows what was applied (10% VIP, $ -4.29) so the cashier can verify on payment. Customers increasingly ask "what's the 5% for" so we make it visible.

6 Internal notes — staff-only (not on customer receipt)

The allergies alert is a critical use case — Sofia flagged the tree-nut allergy and notified KDS. Notes are persistent (don't disappear when scrolled), visually distinct (amber), and timestamp-attributed. Spec §5.4 mandates allergy notes be propagated to kitchen.

7 Activity panel — the differentiation (research §4.3 #5)

Inline audit log, sticky right rail. Every modification to this order is recorded with timestamp + actor + action type. Color-coded by event category (created · kitchen · payment · modification · alert · system). None of the 5 competitor platforms surface a per-order audit log inline. This is a clear UX differentiator and a critical audit/compliance artifact.

8 Pending reviews flagged inline · realtime

The pending discount (#1046 row) sits in the activity log itself, not somewhere separate. Maria sees a row with "PENDING" badge and 2 button actions, all in the same scroll. Decision: Approve in-place; the row updates to "Approved by Maria at 14:38" inline.

Decision points flagged for production

Component shape

Three sections — OrderHeader (status pill, metadata, action bar) · OrderItems (table + totals + approval bar) · ActivityLog (right rail, sticky). All three consume route param :orderId and subscribe to /hubs/orders filtered to that order.

Permission model

Waiter: view own orders, add items. Manager: approve discounts > $5. Cashier: edit payment-only fields. RestaurantAdmin: see full audit + revert last action. Approval bar visibility driven by RBAC claims from JWT (per backend spec).

Realtime strategy

Single SignalR subscription filtered by orderId arriving in JWT. Activity log prepends new rows in-place via React Query useInfiniteQuery with optimistic updates. No full refetch — millisecond-latency feel.

Approval flow

Optimization: "View diff" pre-computes the totals before/after and shows them side-by-side (e.g. 51.36 → 47.07 with VIP). Approve triggers a single PATCH; row badge updates from "PENDING" to "APPROVED by Maria" without scroll. If dispute, "View audit" expands to full timeline.
